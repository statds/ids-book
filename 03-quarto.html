3  Reproducible Data Science

Quarto turns plain-text source into reproducible documents that combine explanation, computation, results, figures, and references. A data-science analysis should be reproducible because readers need to inspect how evidence was produced, not merely see a final picture or a pasted table. Quarto supports Python, R, Julia, and Observable and can publish articles, reports, websites, books, and presentations in several output formats (Quarto Developers, 2025b).

This chapter is a jump start, not a replacement for the complete Quarto Guide. Use the guide when you need options not covered here, and consult the Python documentation, Markdown reference, and presentation documentation for detailed examples (Quarto Developers, 2025d, 2025a, 2025c).

3.1 A Minimal Quarto Document

A Quarto document is a text file whose .qmd extension combines YAML metadata, Markdown prose, equations, citations, and executable code chunks. The following small document is a better starting point than a code-only hello-world: it produces a numerical result, a table, and a figure from the same code that explains them.

Create a file named hello.qmd with YAML metadata like this:

---
title: "Hello, Quarto"
author: "Your Name"
format: html
jupyter: python3
bibliography: references.bib
---

The document can then combine prose, equations, and executable code. Equation punctuation follows ordinary sentence punctuation. The mean of observations \(x_1,\ldots,x_n\) is given by Equation 3.1.

The source syntax for this numbered equation is:

The mean ... is given by @eq-mean.

$$
\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i.
$$ {#eq-mean}

\[ \bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i. \tag{3.1}\]

A cases display can continue a sentence with a comma, as shown in Equation 3.2:

\[ g(x) = \begin{cases} 0, & x < 0,\\ 1, & x \ge 0. \end{cases} \tag{3.2}\]

The comma after the first case and the period after the final case are part of one grammatical statement. The code below generates a table and a figure from the same observations:

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from matplotlib_inline.backend_inline import set_matplotlib_formats

set_matplotlib_formats("svg")

rng = np.random.default_rng(2026)
scores = pd.DataFrame(
    rng.normal(loc=[78, 72, 84], scale=[9, 8, 7], size=(30, 3)).round(1),
    columns=["data science", "statistics", "programming"],
    index=range(1, 31),
)
scores.index.name = "student"
scores.head()

mean_scores = scores.mean()
standard_errors = scores.sem()
fig, ax = plt.subplots()
ax.bar(mean_scores.index, mean_scores, yerr=standard_errors, capsize=4)
ax.set(xlabel="Subject", ylabel="Mean score", title="Simulated class scores")
plt.show()

The call to default_rng(2026) creates a seeded random-number generator, so the simulated 30-student, three-subject score table and Figure Figure 3.1 are reproducible on another computer. The three loc values create subjects with different underlying mean scores. The bar heights are subject means; the error bars show standard errors across students. Quarto itself is documented in the Quarto Guide (Quarto Developers, 2025b).

The opening and closing lines between --- define YAML metadata. Headings use one or more # characters, ordinary text forms paragraphs, dollar signs mark LaTeX equations, and a fenced code chunk begins with ```{python}. The jupyter: python3 setting tells Quarto which Jupyter kernel should execute Python chunks. Expressions whose values are displayed, such as scores, and figures returned by the chunk become part of the rendered document.

Render the document from its directory:

quarto render hello.qmd

Quarto writes hello.html by default. Open that file in a browser, or use quarto preview hello.qmd while editing to render again after each save. Keep the .qmd source under version control; treat the rendered HTML as generated output.

3.2 Markdown Essentials

Markdown provides the readable structure around an analysis. The following mini-report shows how headings, emphasis, a list, a labeled equation, a table, a figure, a citation, and cross-references work together:

## Assessment results {#sec-assessment-results}

The **mean score** summarizes performance in each subject, but it does not show
the variation among students. The sample mean for subject $s$ is

$$
\bar{x}_s = \frac{1}{n}\sum_{i=1}^{n}x_{is}.
$$ {#eq-subject-mean}

Table @tbl-subject-means reports the results calculated with
@eq-subject-mean.

| subject | mean score |
|:--|--:|
| data science | 78.4 |
| statistics | 72.1 |
| programming | 84.3 |

: Simulated mean scores for a class of 30 students. {#tbl-subject-means}

![Mean score by subject, with standard-error bars.](figures/scores.png){#fig-subject-means}

Figure @fig-subject-means makes the difference among subjects easier to see.
The interpretation should also consider the variation, as explained in
Section @sec-assessment-results. The analysis follows reproducible-authoring
practices [@quarto2025guide].

A label in braces, such as {#eq-subject-mean}, identifies an object that Quarto should number. Use the prefixes eq-, tbl-, fig-, and sec- for equations, tables, figures, and sections. A cross-reference begins with @ and uses the matching label, as in @tbl-subject-means. During rendering, Quarto replaces that source text with the current object number. If an earlier table or figure is added, references update automatically instead of leaving a stale number in the prose.

Use a heading hierarchy rather than bold text to organize a document. Put blank lines around paragraphs, tables, and lists; write descriptive link text; keep code that should execute in a Quarto code chunk; and use meaningful captions for figures and tables. Cite sources near the claim they support. The Markdown basics reference covers tables, images, citations, cross-references, callouts, and other features.

3.3 Why the Software Environment Matters

An analysis is a combination of source code and the software environment that interprets it. Two computers can run the same source and obtain different results when they use different Python versions, package versions, operating- system libraries, or default settings. A result that cannot be rerun after an environment changes is not fully reproducible, even when the code is available (Wilson et al., 2017).

An isolated environment makes these dependencies explicit and prevents one project from silently changing another. Recording the Python version and the installed packages lets a collaborator recreate the computational setting, while a lockfile or pinned requirements file records the versions tested here. This practice also makes failures diagnosable: when an upgrade changes an output, we can identify the change instead of guessing which global installation caused it.

3.4 Python Environments for Quarto

Quarto executes Python through a Jupyter kernel, so the interpreter and packages must be installed in an environment that Quarto can find. A virtual environment keeps this project’s packages separate from the system Python and from unrelated projects.

This book uses Python 3.12 in its tested environment. You may choose a virtual environment’s name and location. A virtual environment is a directory containing an isolated Python installation and its packages; it does not contain a project’s source files or build instructions. The uv command-line tool installs Python versions, creates virtual environments, and installs packages; it is not a replacement for Python or Quarto.

uv venv --python 3.12 /path/to/your/environment
source /path/to/your/environment/bin/activate

If uv is unavailable, replace uv venv with python3.12 -m venv and use the same path. Do not install packages into the system Python, and do not commit a virtual-environment directory. Keep the project’s environment specification and source files under version control instead.

Use python --version, which python, and jupyter kernelspec list to verify that the active interpreter is Python 3.12 and is the one you intend to use. If Quarto reports that it cannot find a kernel, select the environment’s Python interpreter in your editor or install its kernel with python -m ipykernel install --user.

3.5 Reproducibility in Practice

Reproducibility requires a record of the inputs, environment, instructions, and decisions that produced an analysis. A Quarto file brings prose and executable code together, but it cannot by itself make an undocumented dataset, unrecorded random seed, or unavailable package reproducible.

For each analysis, preserve these five components:

  1. Source: the .qmd file and any scripts it calls.
  2. Data: the source, version, download date, and transformations for each dataset; keep private or large raw data outside Git when necessary.
  3. Environment: the Python version, package requirements, Quarto version, and operating-system details needed to run the source.
  4. Execution: the commands, options, random seeds, and order of steps used to render the document.
  5. Outputs: tables, figures, and conclusions checked against the source, not manually edited after rendering.

Use relative project paths, pin important package versions, set random seeds when simulation is involved, and render from a clean working tree. These habits make it possible for another analyst to inspect and repeat the work (Wilson et al., 2017).

3.6 Rendering the Book

Rendering the notes locally lets you see how the published book is produced, practice the workflow used in a shared data-science project, and test a correction or improvement before proposing it in a pull request. A successful render shows that the source, computations, citations, and cross-references work together on your computer. To obtain a local copy, clone the repository and enter it:

git clone https://github.com/statds/ids-book.git
cd ids-book

Assume that you have already activated a Python 3.12 environment as described in Section 3.4. The cloned repository contains the Makefile. From its root, install this book’s pinned dependencies and build it:

make install
make check
make render

If you want an environment dedicated to this book, choose a directory for it, create it, and activate it before running those commands. For example, replace /path/to/ids-book-env below with a directory of your choice:

uv venv --python 3.12 /path/to/ids-book-env
source /path/to/ids-book-env/bin/activate

If uv is unavailable, replace uv venv with python3.12 -m venv and use the same path. Activation sets VIRTUAL_ENV, which this repository’s Makefile uses to select Python. The make install target installs the pinned packages from requirements.txt; make check verifies the command-line tools; and make render builds the complete book in _book/. Open _book/index.html in a browser to inspect that completed build. While actively editing the book, make preview starts a local server and rebuilds the output when source files change. Students building the book should not run make req, because that maintainer target rewrites requirements.txt from the local environment.

Read the repository’s Makefile rather than treating its commands as magic. It is a short, plain-text description of the build tasks. Use an AI assistant to ask what a specific target, variable, or command does, then compare the answer with the Makefile and test it with a command such as make -n render, which prints the commands without running them. This is a useful way to learn an unfamiliar project while retaining responsibility for checking the explanation. For a quick test of one source file, use:

make render-one FILE=hello.qmd

Read the terminal output rather than assuming a successful command produced a correct document. Check that code results make sense, links work, figures have captions, citations resolve, and the output contains no accidental secrets or local file paths. Generated _book/, .quarto/, and cache files belong in .gitignore, not in a commit.

3.7 Presentations with Quarto

Quarto presentations should replace the default habit of preparing course work in a proprietary PowerPoint file. A presentation remains plain text, versionable, reproducible, and reviewable while still producing a polished slide deck. Quarto supports reveal.js slides in HTML and can also produce other formats; the presentation guide explains the available options.

A well-made Quarto homework is a reusable professional artifact, not a disposable submission. The same source can become a polished report, research memo, lab note, portfolio piece, or presentation for a different audience by changing its format and explanation while retaining the executable analysis. Students should therefore treat each assignment as an opportunity to practice communicating evidence to people outside this course: clear prose, labeled figures, citations, and a reproducible source record are more valuable than a decorative layout alone (Quarto Developers, 2025b).

Excel, Word, and PowerPoint are useful office tools for administrative staff, but they are not data-science authoring tools. Students should not author data-science assignments in these MS Office formats: their binary contents produce opaque diffs, make line-by-line review difficult, and can preserve hidden formatting or manually edited results without recording how those results were computed. Use a .qmd file, code, data description, and environment as the authoritative record; an HTML rendering is the normal output, and a PDF may be exported only when an audience or assignment specifically requires it. The reason is methodological: a data-science submission must expose executable transformations, preserve data and software provenance, support line-by-line review, and reproduce the same outputs after the source changes. Office files primarily preserve a presentation or a spreadsheet state; they do not reliably preserve that computational record (Wilson et al., 2017).

Plain-text source and Git also provide benefits that office workflows lack. Version history records who changed which lines and makes earlier versions recoverable, rather than hiding revisions in a track-changes pane or a file named final-v2-revised. Code automates repeated calculations, keeps tables and figures synchronized with the data, and can be tested after each change. Several people can review, merge, and reuse the same source without passing around conflicting binary attachments.

Create a presentation by choosing a presentation format in the YAML header:

---
title: "A Data-Science Result"
format: revealjs
---

## The question

What decision does this analysis support?

## The evidence

Explain the important figure and its limitations.

Render it with quarto render presentation.qmd or preview it with quarto preview presentation.qmd. Use headings for slides, keep one central idea on each slide, and write speaker notes when additional explanation belongs in the oral presentation rather than on the slide. Export a PDF only when a course or audience requires a static copy; keep the .qmd source as the authoritative presentation.

Exercises

Complete the Git setup from Chapter 2 and the Quarto installation from Chapter 1 before beginning. Write one .qmd file containing your answers to all problems.

3.1 Follow the complete workflow in Section 3.6 to clone and render this book from source. In the assignment .qmd, report the following evidence:

  1. Record the commands and concise results of git remote -v and git status in the cloned repository.
  2. Record the environment path, the command used to create it (or state that you used an existing environment), and the result of python --version.
  3. Record concise results from make install, make check, and make render. Confirm that the rendered home page is _book/index.html, and describe any error you fixed.
  4. Explain why the virtual-environment directory and _book should not be committed, while the source files, requirements.txt, and _quarto.yml should be tracked.

3.2 Build a small, reproducible analysis in your assignment .qmd. Use the Hello, Quarto Jupyter tutorial as the starting point for its polar-axis figure. Do not create a second document.

  1. Adapt the tutorial’s polar-axis Python code into an executable code chunk, then render the assignment successfully. Give the figure a descriptive caption and label, and refer to it by its automatically generated number in a complete sentence.

  2. Add the displayed equation below using the shown label. In the sentence immediately before or after it, refer to the equation as @eq-polar and explain that it defines the angle used by the Python code.

    \[ \theta = 2\pi r, \qquad 0 \le r < 2. \tag{3.3}\]

  3. From the same r and theta values used for the plot, generate a table of at least five selected pairs. Give the table a caption and label, then refer to it by its automatically generated number in a complete sentence.

  4. Add a BibTeX entry for the Hello, Quarto tutorial to the assignment bibliography, cite it in the prose with its citation key, and verify that the rendered References section contains the entry.

  5. Write two or three complete sentences that interpret the equation, table, and figure together. Include one limitation of this example.

  6. Check that the document has no unresolved citations or cross-references and that its displayed results are generated by the source code. Render the document while saving the messages, then search the log for warnings: quarto render homework.qmd 2>&1 | tee render.log followed by rg -i 'warning|not found|undefined|citation|reference|broken' render.log. Inspect the rendered document for ??, missing labels, and missing bibliography entries. State the checks you performed and any correction you made in the .qmd; do not commit the generated log.

3.3 Make the document ready for reproducible collaboration.

  1. Identify the source files, data inputs, software environment, commands, and outputs another analyst would need to reproduce the work.
  2. Distinguish files that belong under version control from a virtual environment, cache, generated HTML, or other output that should be ignored.
  3. Explain how relative paths, pinned package versions, and a recorded random seed would help another student obtain the same results.
  4. Describe how you would adapt this document into a student-created class- notes contribution without copying instructor-authored exposition.
