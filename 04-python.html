4  Python Practice

Python becomes more useful when you can tell which interpreter runs your code, find the package that supplies a function, design functions with clear inputs and outputs, predict when a change affects an existing object, and recognize the limits of computer number representations. This chapter develops those habits so that short scripts become analyses that another person can inspect and rerun.

4.1 Python Ecosystem

Every Python command runs in one interpreter. That interpreter supplies the language and its standard library; an environment adds third-party packages such as NumPy and pandas. These related terms describe different layers of the Python ecosystem:

Knowing these layers helps you solve ordinary problems. When import pandas fails, you need to determine whether the active interpreter has access to the installed distribution and its importable package. When someone else reruns your work, they need to know which interpreter and installed distributions it uses. The distinctions also help you read documentation, find the source of a function, and avoid installing a package into the wrong environment.

  • Interpreter: The program that runs Python code and supplies the standard library.
  • Module: A unit that Python’s import system loads as a module object. A module can come from a Python source file, a compiled extension, built-in code, or another source.
  • Package: A special module that can contain submodules. A regular package is commonly a directory with an __init__.py file, while a namespace package can span locations and needs no such file.
  • Library: An informal term for a reusable body of code and documentation, such as NumPy or pandas.
  • Distribution: The installable unit managed by tools such as pip. One distribution can provide one or more importable packages or modules.

The standard library includes modules such as math, pathlib, and statistics; NumPy and pandas are third-party libraries rather than parts of Python itself (McKinney, 2022; Python Software Foundation, 2026c).

When code fails with ModuleNotFoundError, first determine which interpreter is active. The following chunk reports the interpreter path and version used by the current Quarto document:

import sys

print(sys.executable)
print(sys.version.split()[0])
/home/junyan/work/teaching/ids-book/.ids/bin/python3
3.12.14

In a terminal, python --version and which python provide similar evidence after an environment has been activated. Use python -m pip, rather than a bare pip, to ensure that package management uses that same interpreter:

python -m pip show numpy
python -m pip show pandas
python -m pip freeze

A virtual environment is a self-contained directory with a chosen Python installation and its packages. It prevents one project’s package version from silently changing another project’s behavior. The exact package versions in requirements.txt are part of a reproducible analysis because another person can install the same set with python -m pip install -r requirements.txt (Python Software Foundation, 2026d; Wilson et al., 2017). Chapter 3 showed how this book uses the .ids environment; the important practice here is to check the interpreter, not merely the command prompt.

4.2 Imports

An import statement binds a name in the current file to a module or an object defined elsewhere. Choose imports that make the source easy to read and avoid names that obscure where a function comes from:

import math
from pathlib import Path

project_root = Path.cwd()
print(math.sqrt(81))
print(project_root.name)
9.0
ids-book

For widely used data-science libraries, conventional aliases make code easier to recognize:

import numpy as np
import pandas as pd

Avoid from package import *. It hides the source of each name, can overwrite an existing name, and makes a traceback harder to interpret. When you need to learn what an imported object does, use help(), inspect its documentation, or check its type and attributes deliberately:

sample = np.array([2, 4, 8])

print(type(sample))
print(sample.dtype)
print(sample.shape)
<class 'numpy.ndarray'>
int64
(3,)

The type, dtype, and shape attributes answer different questions. The first identifies the Python or library object; dtype describes how an array stores its values; and shape gives its dimensions. Checking all three is often more informative than printing a large object.

4.3 Functions

A function should name a task, accept the data and choices needed for that task, and return a result that another part of the analysis can use. It should not quietly depend on a global variable or print a result that a later step needs to analyze. A docstring records the function’s contract, while type hints communicate the intended inputs and output; Python does not automatically enforce those hints.

The function below summarizes numeric values without changing its input. It converts the input to a floating-point NumPy array, checks a precondition, and returns a dictionary whose named fields are convenient in prose and tables.

def summarize(values: list[float] | np.ndarray) -> dict[str, int | float]:
    """Return the count, mean, and sample standard deviation of values."""
    data = np.asarray(values, dtype=float)
    if data.ndim != 1 or data.size < 2:
        raise ValueError("values must be a one-dimensional sequence of length 2 or more")
    return {
        "n": int(data.size),
        "mean": float(data.mean()),
        "sd": float(data.std(ddof=1)),
    }

summary = summarize([82, 91, 87, 76, 94])
summary
{'n': 5, 'mean': 86.0, 'sd': 7.176350047203662}

The conversion inside summarize creates an array suited to numerical work. The function therefore accepts an ordinary list but does not force every caller to learn NumPy’s input rules. Its explicit ValueError gives a useful message at the boundary of the function, instead of allowing a mysterious result later in the analysis.

Run a small, direct check whenever you write a function. This is not a complete test suite, but it records a known case and catches an accidental change to the function’s behavior:

expected_mean = 86.0
assert summarize([82, 91, 87, 76, 94])["mean"] == expected_mean

Use a function when a task recurs, when its name clarifies a multi-step calculation, or when you want to test one part of an analysis independently. Do not turn every one-line expression into a function; an unnecessary function can hide a simple calculation.

4.4 Names and Objects

Python names refer to objects. Assignment usually binds another name to the same object; it does not copy that object. Every object has an identity, type, and value. Lists and dictionaries are mutable, while numbers, strings, and tuples are immutable (Python Software Foundation, 2026b).

scores = [82, 91, 87]
alias = scores
copy = scores.copy()

alias.append(76)

print(scores)
print(alias is scores)
print(copy)
print(copy is scores)
[82, 91, 87, 76]
True
[82, 91, 87]
False

The call to append changes the list object that both scores and alias refer to. The copy variable refers to a distinct list, so it retains the earlier values. Use is only to ask whether two names refer to the same object; use == to ask whether their values are equal.

This distinction matters at function boundaries. The first function below has a side effect: it modifies the caller’s list. The second creates and returns a new list, which is generally safer for a data-analysis transformation.

def add_bonus_in_place(values: list[float], bonus: float) -> None:
    """Add bonus to each value by changing values itself."""
    for index in range(len(values)):
        values[index] += bonus


def with_bonus(values: list[float], bonus: float) -> list[float]:
    """Return bonus-adjusted values without changing values itself."""
    return [value + bonus for value in values]


original = [82, 91, 87]
adjusted = with_bonus(original, 3)
add_bonus_in_place(original, 3)

print(adjusted)
print(original)
[85, 94, 90]
[85, 94, 90]

Neither style is universally correct. Mutating a large object can be efficient, and some library methods intentionally modify objects in place. The important rule is that a function’s name, docstring, and use should make mutation clear. When in doubt, assign a returned object to a new, descriptive name and retain the original until you have checked the result.

4.5 Data Structures

Lists are flexible containers that can hold objects of different types. NumPy arrays store a regularly shaped collection of values of one dtype, which makes elementwise numerical operations concise. A pandas data frame organizes named columns that can have different types. Select the structure that matches the task, rather than treating them as interchangeable.

values = [1, 2, 3]
array = np.asarray(values, dtype=float)
table = pd.DataFrame({"student": ["A", "B", "C"], "score": array})

print(array * 10)
table
[10. 20. 30.]
student score
0 A 1.0
1 B 2.0
2 C 3.0

The expression array * 10 multiplies every array value. In contrast, values * 10 repeats the list ten times. This is not a minor syntactic detail: it changes the object type and the meaning of the operation. Convert to an array when you need regular numerical computation; use a data frame when the observations have named variables and you need to inspect, join, summarize, or plot columns (McKinney, 2022; VanderPlas, 2016).

4.6 Number Representation

Python’s built-in integers grow to represent arbitrarily large whole numbers, subject to available memory. NumPy integers have a fixed width, such as int8 or int64, because fixed-width storage supports compact arrays and fast operations. A value outside that type’s range can overflow:

largest_int8 = np.array([127], dtype=np.int8)
overflowed = largest_int8 + np.array([1], dtype=np.int8)

print(largest_int8.dtype, largest_int8)
print(overflowed)
int8 [127]
[-128]

Inspect dtype before converting identifiers, counts, or monetary values to a small integer type. An overflow may produce a plausible but wrong value, which is more dangerous than a visible error.

Most numerical analysis uses binary floating-point values. Many decimal fractions, including 0.1, have no exact finite binary representation, so a stored float is usually an approximation. This behavior comes from the hardware representation, not from a Python mistake (Python Software Foundation, 2026a).

import math

total = 0.1 + 0.1 + 0.1
target = 0.3

print(total == target)
print(format(total, ".17f"))
print(math.isclose(total, target))
False
0.30000000000000004
True

Use exact equality for values that are expected to be exactly equal, such as category labels, integer counts, or a known string. For computed floating-point values, use math.isclose or numpy.isclose with tolerances chosen for the scale and purpose of the analysis. Format a final result for readers, but do not mistake rounded display for increased computational accuracy. Use decimal.Decimal when an application requires decimal arithmetic, such as currency calculations with legally defined rounding rules.

4.7 Simulation

Random simulation is a compact setting in which all of these ideas matter. The Monty Hall game has three doors, one prize, and a host who opens an unchosen empty door. A player who switches wins whenever the first choice was wrong, which has probability two-thirds. The function below uses a local NumPy random number generator. Supplying the same seed creates the same pseudo-random draws, which makes debugging and review possible.

def simulate_monty_hall(
    n_trials: int, seed: int | None = None
) -> pd.DataFrame:
    """Estimate stay and switch win rates in the three-door Monty Hall game."""
    if n_trials <= 0:
        raise ValueError("n_trials must be positive")
    rng = np.random.default_rng(seed)
    prize = rng.integers(0, 3, size=n_trials)
    first_choice = rng.integers(0, 3, size=n_trials)
    stay_wins = (first_choice == prize).sum()
    switch_wins = n_trials - stay_wins
    return pd.DataFrame(
        {
            "strategy": ["stay", "switch"],
            "wins": [stay_wins, switch_wins],
            "win_rate": [stay_wins / n_trials, switch_wins / n_trials],
        }
    )


monty_results = simulate_monty_hall(n_trials=100_000, seed=2026)
monty_results
strategy wins win_rate
0 stay 33260 0.3326
1 switch 66740 0.6674

The function returns a data frame instead of printing a conclusion. That choice lets later code make a table, a figure, or a formal comparison without parsing text. Repeating the call with the same arguments should reproduce the result:

repeat_results = simulate_monty_hall(n_trials=100_000, seed=2026)
assert monty_results.equals(repeat_results)

np.isclose(monty_results.loc[0, "win_rate"], 1 / 3, atol=0.01)
np.True_

The tolerance in the last line reflects simulation variability, not floating-point error alone. State why a tolerance is appropriate whenever you choose one; a tolerance that is too loose can conceal a mistake.

4.8 Debugging

When an analysis gives an unexpected result, reduce the question before changing the code. Check the interpreter and package version, then inspect the smallest object that could explain the behavior. A concise diagnostic sequence often looks like this:

print(type(monty_results))
print(monty_results.dtypes)
print(monty_results.shape)
print(monty_results.head())
<class 'pandas.DataFrame'>
strategy        str
wins          int64
win_rate    float64
dtype: object
(2, 3)
  strategy   wins  win_rate
0     stay  33260    0.3326
1   switch  66740    0.6674

Read the final line of a traceback first: it usually states the exception type and message. Then find the line in your source that led there. Avoid solving an error by repeatedly installing packages, restarting the editor, or changing several unrelated lines at once. Make one hypothesis, test it with a small example, and record the correction in the source or a concise commit message.

Exercises

Write one .qmd file containing your answers to all problems. Use the same Python 3.12 environment that you created for Chapter 3.

4.1 Inspect the Python environment that will run your analysis.

  1. In an executable Python chunk, display sys.executable, sys.version, and the versions of NumPy and pandas. Include the resulting output in the rendered .qmd.
  2. In a terminal, run python -m pip show numpy and python -m pip show pandas. Record the commands and the package version and location reported for each package.
  3. In two or three sentences, distinguish the interpreter, the standard library, a module, a package, and a virtual environment. Name one example of each from this chapter.
  4. State one concrete symptom that would make you suspect that Quarto or your editor is using the wrong Python environment, and give the first command or setting you would check.

4.2 Write and check functions with clear object behavior.

  1. In your .qmd, reproduce the add_bonus_in_place and with_bonus functions from this chapter. Call both functions on a list named scores, then show scores before and after each call.
  2. Add assert statements that verify that with_bonus leaves its input list unchanged and that add_bonus_in_place changes its input list by the stated bonus.
  3. Write a function named summarize_scores that accepts a one-dimensional sequence of at least two numeric scores and returns a dictionary with the keys n, mean, minimum, and maximum. Include a docstring and type hints, then show the returned dictionary for [82, 91, 87, 76, 94].
  4. Give one example of a situation in which in-place mutation is useful and one in which returning a new object is safer. Explain each choice in one or two complete sentences.

4.3 Use numerical types and random simulation deliberately.

  1. Reproduce the int8 overflow example from this chapter. Include the array’s dtype, the value before addition, and the value after addition, then explain why the result is not a valid count.
  2. Show that 0.1 + 0.1 + 0.1 == 0.3 is false on your system. Use math.isclose to make the intended comparison, and explain why equality and closeness answer different questions.
  3. Reproduce simulate_monty_hall from this chapter. Run it twice with n_trials=100_000 and seed=2026, and use an assertion to show that the returned data frames are identical.
  4. Run the simulation with seed 2027. Give the two estimated win rates and compare each with its theoretical value, \(1/3\) for staying and \(2/3\) for switching. State a tolerance you used and why it is reasonable for this simulation size.

4.4 Extend the Monty Hall simulation to a general number of doors.

  1. Write play_general_monty_hall(n_doors, n_empty, rng) to simulate one game. Require n_doors >= 3 and 0 < n_empty <= n_doors - 2. After the player selects a door, the host must open n_empty unchosen doors that do not hide the prize. For the switching strategy, choose uniformly among the remaining unopened doors other than the player’s initial choice. Return the outcomes of both the stay and switch strategies.
  2. Play the three-door game with one empty door opened by the host several times. Display the individual results and explain how the host’s choice follows the rules in each game.
  3. Play the 10-door game with eight empty doors opened by the host several times. Display the individual results and explain how the switching choice differs from the three-door game.
  4. Write simulate_general_monty_hall(n_doors, n_empty, n_trials, seed) to call the one-game function repeatedly. Require n_trials > 0, create one seeded random-number generator for the simulation, and return a data frame with one row each for stay and switch, including wins and win rate.
  5. Apply the simulation with (n_doors, n_empty) equal to (3, 1) and (10, 8), both with n_trials=1_000 and seed=2026. Render a table that summarizes the results.
  6. Calculate the theoretical win rates: \(1/n\) for staying and \((n-1) / [n(n-m-1)]\) for switching when there are \(n\) doors and the host opens \(m\) empty doors. Compare the simulations with these values and explain which strategy is preferred in each setting.
  7. Call the simulation twice with identical arguments and use an assertion to show that it returns identical results. Explain why this check matters.

4.5 Estimate \(\pi\) with Monte Carlo simulation.

  1. Write estimate_pi(n, seed) using numpy.random.default_rng. Generate n points uniformly in the square from \(-1\) to \(1\) in both coordinates. Return the estimate of \(\pi\) and a 95% normal-approximation confidence interval based on the proportion of points inside the unit circle. Validate that n is positive.
  2. Run the function with sample sizes 1,000, 2,000, 4,000, and 8,000, using a different documented seed for each run. Render a table containing the sample size, estimate, interval bounds, and whether the interval contains \(\pi\).
  3. Write a second function that repeats the experiment 1,000 times for one sample size and returns the proportion of intervals that contain \(\pi\). Apply it to all four sample sizes with a fixed seed, then plot empirical coverage against sample size with a horizontal reference line at 0.95.
  4. Explain why a 95% confidence interval need not contain \(\pi\) in every individual run, and explain what the coverage results say about the method.

4.6 Reproduce the Google Billboard Ad by searching the digits of \(e\) with the Python standard library.

  1. Write a function that computes at least 200 decimal digits of \(e\) with decimal.Decimal, then returns the digits after the decimal point as a string. Set the decimal context precision inside the function rather than relying on an editor or notebook setting.
  2. Write is_prime(n) using math.isqrt and trial division. It must return False for integers less than 2 and avoid testing divisors larger than the square root of n.
  3. Scan consecutive 10-digit strings in the fractional digits of \(e\) and find the first one that represents a prime number. Report the prime and its zero-based starting position after the decimal point. Use an assertion or a documented loop result to show that no earlier 10-digit string is prime.
  4. Explain why using float would be unsuitable for this search and why the decimal context belongs in the function rather than in hidden notebook state.

4.7 Play Game 24 by searching arithmetic expressions. Given four card values, use every value exactly once with the operations \(+\), \(-\), \(\times\), and \(/\) to make 24. Parentheses determine the order of operations. Let \(\square\) represent one of the four card values and let \(\bigcirc\) represent one of the four operations. For example, \((\square \bigcirc \square) \bigcirc (\square \bigcirc \square)\) is one possible expression form.

  1. List all distinct ways to group four card values with parentheses. Use \(\square\) and \(\bigcirc\) notation, and state how many groupings there are.
  2. Count the maximum number of candidate expressions that a brute-force solver could examine before removing equivalent expressions. Account for the five parenthesizations, all orders of four card values, and the four choices for each of three operations.
  3. Write solve_24(cards) for a list of four integer card values. The function must use every card exactly once and return the fully parenthesized expressions that equal 24. Use brute force to enumerate the five groupings, every order of the card values, and every choice of operations. Use fractions.Fraction for arithmetic, so a valid solution is not lost to floating-point rounding. Do not remove duplicate solutions yet.
  4. Write unique_solutions(expressions) to remove duplicate solutions from the brute-force output. Treat expressions that differ only in the order of the operands of addition or multiplication as duplicates. Describe the normalized representation you use to make that decision.
  5. Test both functions with [1, 3, 9, 10], [4, 4, 10, 10], [1, 5, 5, 5], [3, 3, 7, 7], [3, 3, 8, 8], and [1, 4, 5, 6]. Render one solution for each hand, report the number of solutions before and after deduplication, and use assertions to verify that every displayed expression has value 24. Include one hand with no solution and assert that its result is empty.
  6. Explain why brute force is feasible for four cards but would become costly with more cards. Explain why exact fractions are preferable to floating-point values for this task.
